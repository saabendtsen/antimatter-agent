# Antimatter Agent

A local-model experiment for playing [Antimatter Dimensions](https://ivark.github.io/AntimatterDimensions/) through a visible browser. [homelab-workspace#369](https://github.com/saabendtsen/homelab-workspace/issues/369) records the experiment contract.

The model uses Pi with only three tools: a Playwright-backed game browser, bounded warm/cold memory, and a round-finishing decision. Each round has a fresh agent session. A playthrough keeps its game save and notes. A successor playthrough receives only a handoff of up to 150 words.

Every playthrough starts a new game from a fresh browser save (its own browser profile); no game state crosses playthroughs. In pre-pilot runs 1 and 2 the model wrote its game state into the handoff ("6.36 Qa/sec, 13/20 5th Dimensions"), and the next playthrough's retrospective called those numbers "stale or hallucinated" because its fresh game did not match them. The round system prompt, the first round prompt, and the retrospective instructions therefore state the reset and that state numbers in an inherited handoff are historical observations from an earlier game, not current state. They do not restrict what the handoff contains; its content stays the model's choice. The retrospective's `inheritedAssessment` rates the handoff the playthrough received. Pre-pilot run 1 received none but stored `useful`, with a reason about its own play. When no handoff was inherited, the harness now always stores `none`: it keeps the model's reason if the model itself answered `none`, and otherwise stores `No handoff was inherited, so there was nothing to assess.` with `assessmentNormalized: true` and the model's original `modelInheritedAssessment` and `modelReason` for review. A mislabelled absent handoff never fails the retrospective; a missing or over-150-word successor handoff still does.

A round can contain a sequence of up to 120 browser actions and 300 browser/memory tool calls. The model normally ends it by calling `finish_round` and choosing a wake time. A round lasts at most 20 minutes. After 15 minutes, browser actions and note retrieval close and the model is told, in tool results and a steering message, to write notes and call `finish_round`; the final five minutes are reserved for that. A model that ends its turn without calling `finish_round` gets one reminder. A round that still has not called `finish_round` at 20 minutes is aborted and recorded as incomplete with `incompleteReason: "round_time_limit"` (or `"no_finish_round"` after an ignored reminder); three consecutive incomplete rounds block the playthrough. A round never outlasts the playthrough: near its deadline the round is shortened by cutting action time, not the finish period, and a round is not started with less than seven minutes left (two action minutes plus the five-minute finish period; the first model response of a round took 24–72 seconds in pre-pilot run 2). Pi compaction is disabled inside these fresh sessions; the configured local endpoint currently offers about 120,000 context tokens, while the automatically loaded warm note is limited to 2,200 characters. At 70% estimated context occupancy, the harness stops browser actions and note retrieval but still permits note writes and `finish_round`. Each round records its peak estimated context tokens and percentage of the configured window. Early pre-pilot rounds used 4–28% of context with the earlier 12-action/30-call caps; the larger caps test whether those limits constrained useful progress. With those larger caps, the first two rounds of pre-pilot run 2 reached the former eight-minute cap at about 29% of context (31 and 26 browser actions) and were cut off mid-action without `finish_round`. Those turns took about 13.5 seconds and added about 1,070 context tokens each. Pre-pilot run 3 round 1 kept a similar pace (about 15 seconds per turn) and was at about 53% of context after 15 minutes and 56.6% (67,868 tokens, 42 browser actions) when its 16-minute action period closed. It then lost the round: a click already in flight was blocked, the queued steering message followed, and the next model request produced no output in the remaining 117 seconds of the former two-minute finish period, while ordinary turns reused the server's prompt cache and took about 15 seconds. A note write at that context size had taken about 43 seconds. Pre-pilot run 2 round 7, which finished 13 seconds after its cutoff at 42.7%, had already started its `finish_round` turn before the steering message was delivered. The 15-minute action period therefore still reaches roughly half the context window at the observed pace, and the five-minute finish period leaves room for a slow first request after the cutoff, a note, and `finish_round`. Slower turns can still end the action period below 50%; faster rounds can reach the 70% ceiling first.

The browser tool exposes visible page text, controls, navigation, clicks, and screenshots. The current text-only local model uses text and controls; screenshot results are available when the configured model accepts images. The separate public viewer always receives screenshots.

## Run on the development PC

The existing `local-llm-worker` endpoint must be healthy, and Pi must have `local-worker/local-worker` configured. By default the harness uses Pi's configured loopback endpoint. If the worker is already bound to the LAN address, set `ANTIMATTER_MODEL_URL` to its `/v1` URL and `ANTIMATTER_MODEL_KEY_FILE` to the existing key file outside Git. The key is loaded by the host process and is never a player tool or prompt. With Node.js 22 or later:

```cmd
npm ci
npx playwright install chromium
npm test
npm run test:e2e
npm run smoke
npm start
```

`npm start` runs the three-playthrough pre-pilot. Each playthrough stops at 30 rounds or one hour; with 20-minute rounds, a one-hour playthrough has at least two full rounds and a third whose action period loses only the harness's few seconds of start-up, capture and checkpoint time. The controller keeps its state in ignored `state/prepilot/`; restarting it resumes the same playthrough and browser profile. The game browser stays open between rounds. During the pre-pilot, rounds start immediately after the prior round's checkpoint; the model's requested wake is logged but not applied. `node src/controller.js --soak` runs one separate four-hour playthrough in ignored `state/soak/` to check whether the player stays consistent over a longer run before the pilot. It applies the model's requested wake time, which `finish_round` already bounds to 20–600 seconds, so the soak exercises the same waiting behaviour as the pilot while a four-hour run still gets about 8 rounds even at the maximum pace (a maximum wait plus a maximum 20-minute round is 30 minutes). The soak ends at four hours, at 480 rounds (a runaway guard that normal pacing should not reach), or when the model claims Infinity. Round, tool, memory, context, handoff, and publishing limits are the same as in the other modes. The public viewer measures staleness from the later of the last update and the planned next round, so a planned wait of up to 10 minutes does not appear stale. Use `node src/controller.js --pilot` only after reviewing the pre-pilot; the pilot uses a separate state directory, applies the model's requested wake time, and has a 24-hour limit.

Each controller start records the harness source it runs as `harness` in `control.json`: `{ commit, dirty, source }`, where `source` is `git` (from `git rev-parse HEAD`, with `dirty` true when tracked files differ from that commit), `env` (a well-formed `ANTIMATTER_SOURCE_COMMIT`, for a copy without Git), or `unknown` with a `reason` code (`git_unavailable` when Git or the repository is missing, `git_unrecognised` when its output is not a commit) when neither is available. Missing Git never stops the controller. A new playthrough stores the same value in its control entry and its `run_start` event. When a restarted controller picks up an unfinished playthrough (active or awaiting its retrospective), it logs `controller_resume` with the current `harness`, the previous controller's `previousCommit`, the playthrough's `runStartCommit`, `commitChanged` (`null` if either commit is unknown), and `gapSeconds` since the playthrough's last event. Pre-pilot run 2's resume on 2026-09-26 had its commit written into an `operator_resume` event by hand. Provenance stays in local state and is not published; it holds no paths, command output or environment values. Git runs in the controller process only; the player still has no shell or file access.

The run history stays under `state/`. Each playthrough's `transcript.jsonl` records completed user, assistant, and tool-result messages with text, tool calls, token usage, and any thinking blocks Pi returns. Image payloads and provider metadata are omitted. The transcript is local and ignored by Git; it is not sent to the public viewer. Pi thinking is set to `off`, but the local model still returns thinking blocks: pre-pilot run 3's transcript has 190 of them across its 194 assistant messages. Earlier rounds cannot be reconstructed from the new transcript. `publication/latest.json` and `publication/screen.png` are the reduced public view. The controller rewrites them when a playthrough starts (before its browser opens, with no screenshot or page text), when each round starts (from the harness's own observation and screenshot, taken before the round timer and the model start), when each round ends, and when a playthrough moves to its handoff. `current.phase` is `starting`, `playing`, `waiting`, or `reviewing`; a playing round also carries `roundStartedAt` and `roundEndsBy`. The current block is only carried forward within one playthrough, so a new playthrough never shows the prior game's screenshot, page text, decision, or wake time. Start the publisher separately after the server viewer is deployed:

```cmd
npm run publish
```

The publisher uses the configured `home-server` SSH alias and sends only those two public files to `/srv/homelab-deploy/antimatter-agent/data`. Override the destination with `ANTIMATTER_PUBLIC_HOST` and `ANTIMATTER_PUBLIC_DIR` if the approved server wiring differs. The player has no shell or publisher tool.

## Runtime contract

The viewer image serves static HTML on port 8080 and returns 200 at `/health`. The page polls `data/latest.json` every 30 seconds and renders every field as text. Its status banner shows `Live`, `Stale` (no new `updatedAt` for 24 minutes, counted from the later of the last update and the planned next round, while the run is active; a legitimate 20-minute round plus checkpoint, capture and the 60-second publisher interval stays below that), `Offline` (the last fetch failed; the last received data stays visible), `Finished`, or `Stopped — needs attention`. It only loads a screenshot whose name is a plain image file name, such as `screen.png?v=123`. Mount the public data directory read-only at `/srv/data`. The app is read-only and needs no database or secret. The server-specific Compose and Caddy route belong to `saabendtsen/home-server`.
